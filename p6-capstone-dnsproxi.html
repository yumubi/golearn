P6 · Capstone：go 版 dnsproxi（对照你的 Rust 载体 D1-D7） ​

你在 _rust_learning 线⑤用 Rust 把 dnsproxi 从 D1 写到 D7（负缓存、 TinyLFU 准入、主动老化，24 个单测、全部实测）。现在用 Go 复刻， 每一课都有你自己的 Rust 代码做对照：这是这套课的收官项目。

怎么读这章 ​

这是一份工程复盘日志，不是教程：G1 到 G6 每一段都是一次实测验收 （跑通什么、数字是多少）加教训（翻车在哪、修法是什么）。按 G1→G6 顺序读，起手小节告诉你下一步装什么，复盘小节给实拍表格和 Go vs Rust 实感。文中的阶段规划表保留原样；"对照你 Rust 版"全部指向 _rust_learning 线⑤的 D1-D7 代码。复盘内容未改写，历史价值在原话。

为什么是 dnsproxi ​

  • UDP 无连接 + 每查询临时 socket（D1）→ goroutine 生死管理和 channel 的天然练习
  • 共享缓存（D2-D7）→ P3 的 sync 决策树 + 你 D4 sample-K、D5 FreqSketch 在 Go 里重写一遍（atomic.Pointer 换 ArcSwap，sync.Map/分片锁换 RwLock）
  • TTL 主动老化（D6）→ time.Ticker + 后台 goroutine 的生命周期管理
  • 字节解析（DNS 报文头、压缩指针）→ Go 的 encoding/binary + []byte 切片，对照 Rust 的 &[u8] + try_get：没有借用检查的世界里 怎么安全切 buffer，这是 Go 的核心功课

Go vs Rust 实感（对照你 Rust 版 D2） ​

  1. 解析器从"函数返回 Option"变成"结构体 + error"。Rust 版 question()/records() 返回 Option<(String,u16,usize)>，一行 ? 走完； Go 版 ParseQuestion 返回 *Question 结构体，每个字段显式赋值。代码长 30%，但调用点可读性反而高：q.Name vs q.0。
  2. Entry 是纯值类型，不需要 AtomicU64。Rust 版 last_access 是 AtomicU64（读锁下原子写，近似 LRU）；Go 版 D2 档直接砍掉这个字段， 惰性过期 + RWMutex 读路径零写。AtomicU64 是 D3 sample-K 的前置，到时候 Go 用 sync/atomic 照抄 fetch_max 语义。
  3. TTL 倒计时的偏移不变量，两个语言都要手工维护。question 段长度 必须相等，否则指针偏移错位 这个判据，Rust 用 end != old_end 三行， Go 同样三行。跨语言教训：字节级协议的不变量检查是语言无关的， 谁都逃不掉，谁都不能偷懒。
  4. 冒烟踩坑（比 Rust D2 深一层）：macOS dig 9.10.6 默认置 EDNS OPT （ARCOUNT=1）+ AD 位（byte3=0x20）。+noedns 消 EDNS、+cd 消不掉 AD（只加 CD），+noad 才是"纯 RD=1 查询"。cache.Request 拒收 flags2!=0 是刻意的（对齐你 Rust 版 buf[3] != 0），冒烟脚本的 dig 参数就是这节课的作业答案。定位手法：裸 python 客户端一发即中（hit）， dig 两发全 miss → 差异在客户端 flags → hex dump 上游收到的包 （0120 vs 0100）→ 对表 AD 位。
  5. fake upstream 升级为带计数。collections.Counter per-(qname,qtype) 计数，每次查询打 [upstream] qname type=T hit=N。这行输出就是缓存 端到端的判据（上游只见 2 次 = miss + 过期重取）；对照你 Rust 版 run.sh 里靠 dnsq.py 输出 answers 字段逐发人工对账（D1 线的 dns-upstream 本身不带计数，这个 Counter 是 Go 版新加的）。 测试基础设施一开始就为可观测性服务。

Go vs Rust 实感（对照你 Rust 版 D5） ​

  1. AtomicU64 数组 → atomic.Uint64 切片。Rust Vec<AtomicU64> 一行； Go make([]atomic.Uint64, n) 同样直白（atomic.Uint64 是 Go 1.19+ 的 对应物，别用 []uint64+atomic.LoadPointer 自虐）。CAS 循环照抄： CompareAndSwap(cur, cur+1<<shift)，饱和判据 (cur>>shift)&0xF == 0xF。 位运算部分两语言逐字同构，你 Rust 课文说"位运算一样"，实测如此。
  2. fetch_update → Load+Swap。Rust 减半用 fetch_update（CAS 到成功）；Go 版采用 Swap((Load()>>1)&mask)，可能覆盖并发增量，这是近似计数的一项取舍，不能推广成精确计数的安全替代。
  3. pickVictim 的 expired 判据。你 Rust 版是 DNS_CACHE_VICTIM_EXPIRED_FIRST 旋钮 + 排序键字典序；Go 版简化成 "始终检查挑中者死活"（排序仍纯 last_access）。少一个旋钮、语义同向： 尸体在准入里无条件输。D6 上主动老化时再评估要不要补字典序。
  4. 翻车×2，都被测试抓住：① pickVictim 里调了两次 sampleIndices （一次建 candidates、一次换算下标），RNG 前进导致两个不同的样本， 下标换算全乱。修法：只调一次，统一成"候选下标集合"。教训同 D3： RNG 是状态机，调两次就漂移。② NewSketch 的 doorMask 三目表达式 手滑写进 doorMark 函数体，gofmt 过了但 vet 报语法错，说明格式化 工具不背语法正确性的锅。
  5. 准入的语义红利在日志里看得见：msg:"cache reject" qname:cold.test cand_freq=1 victim_freq=5 这行日志同时给出了判决依据（双方频率）和结果。 可观测性不是事后加的，是判决函数顺手返回的（Admit 只返回 bool， 频率在 PutFull 里已知，日志信息零成本）。

G5 起手 ​

对照你 Rust 版 D6：主动老化（Redis activeExpireCycle）。Go 版 cache/expire.go：time.Ticker 每 1/hz 秒醒，每轮随机抽 sample 个 slot 当场判当场删（一次抽一个，不能先攒批再删：swap_remove 会让记住的 下标指向别人，静默删活人），25% 过期率高就再来一轮，墙钟预算用完就停。 入口：DNS_CACHE_ACTIVE_TTL/DNS_CACHE_EXPIRE_HZ。

Go vs Rust 实感（对照你 Rust 版 D6） ​

  1. 结构同构，goroutine 替代 tokio::spawn。你 Rust 版 tokio::spawn
    • interval(Duration::from_millis(1000/hz))；Go 版 time.NewTicker
    • goroutine + done channel 关停。间隔算术两版同款 1000/hz 毫秒 ：两版都要限制 hz；Go 的 time.Second / time.Duration(hz) 在 hz=0 时整数除零会 panic，hz 过大时计算出的间隔也可能为零，NewTicker 不接受非正间隔。因此 envIntClamp 的范围限制不能省。
  2. 锁边界翻译得更直白。Rust 版 let (checked, removed) = { let mut c = cache.write(); c.expire_round(...) };：花括号就是锁的生死线。 Go 版 ExpireRound 自带 Lock/defer Unlock，多轮之间锁天然释放， 排队的查询能插进来。语言没有作用域锁的语法糖，反而逼你把边界 想清楚：每轮一个函数，锁的边界 = 函数边界。
  3. Pct 默认 10 不是 25。你 Rust :857-864 的源码考据先行：25 是 SLOW_TIME_PERC（CPU 预算百分比），现行 Redis 判据是 ACCEPTABLE_STALE=10，坊间的 25% 是两个常量张冠李戴。Go 版注释 直接引用这个考据：先查证再写默认值。
  4. 测试翻车×1：不是 bug，是抽样统计。换位陷阱测试期望 50 轮收干净 200 具尸体，实测 removed=163：有放回 20 抽/轮 × 50 轮 = 1000 抽， 本来就覆盖不满 200/800 密度的全部尸体（探针证实 alive 600 条无一 误伤）。轮数拉到 500 全绿。教训：断言统计目标前先算覆盖概率 差点把"没删完"误判成"误删活人"，方向正好相反。
  5. Ghosts() 的成本观两版通用。Rust :995 注释原话"没有它，主动老化 其实没跑起来会是一次安静的失效"。Go 版同款 RLock 全表扫，测试 与调试用，生产别开（ghost_gauge 默认关的理由）。

Go vs Rust 实感（对照你 Rust 版 D3/D4） ​

  1. Entry.slot 字段 → 反向 map。Rust 把 slot 存在 Entry 里（逐出时 swap_remove + 修正被换位条目的 slot，一处写）；Go 版用 map[Key]int 反查表（同样一处写，但多一张表要同步）。三张表（keys/slot/m）必须 一起动，第一版 removeSlot 漏删 m，len=4 keys=3 m=4，容量上限静默失效， 被测试当场抓住。教训：Rust 的 struct 字段是编译器帮你绑定的不变量， Go 的平行 map 是你自己守的。
  2. AtomicU64 → 写锁升级。Rust 版命中时在读锁下 fetch_max 更新 last_access（"读变写"难题的原子解）；Go 的 map 没有原子，Get 命中 必须升级写锁。这就是你 Rust 课文 §"严格 LRU"那段说的代价在 Go 的 实相：没有原子可借时，读多写少的 RwLock 优势直接打折。第一版我 把 touch 留在 PutFull、Get 只读，端到端立刻翻车：ev2 刚命中却被逐出 （它的 last_access 还停在插入时刻）。"命中必须变热"不是优化，是 LRU 的定义。
  3. Floyd 抽样一行不差地抄。for j in len-k..len { candidate = random(j+1); if dup { j } else { candidate } } ：Rust 和 Go 逐字对应。这类算法 的正确策略就是信源码，别"用自己的话重写"。
  4. fake clock 注入。测试用 NowMs = func() uint64 { return fc.ms } 替换逻辑时钟，last_access 完全可控。你 Rust 版测试传 now_ms 闭包； Go 的包级 var 替换更粗暴（测试串行时才安全），但够用。

Go vs Rust 实感（对照你 Rust 版 dnsproxi 同功能） ​

  1. 报文解析要显式检查边界。Rust 版的 try_get 返回错误，Go 的切片索引越界会 panic；Rust 普通索引也可能 panic。这与借用检查是不同的问题，Go 版 ParseName 在访问前检查位置。
  2. per-query 生命周期靠纪律。tokio::spawn 有 JoinHandle 管； go handleQuery() 谁也不等：Run 里 WaitGroup + ctx-close-监听口
    • 入口 recover 三件套缺一不可。P3 问题 1 的实弹版（goroutine panic 防御）。
  3. UDP deadline 是救命的。上游黑洞场景，没有 SetDeadline 的版本 goroutine 永久挂死（TestD1Timeout 3s 抓到）。L9 的 "bound your resources" 在 Go 的对应物 = 每个 socket 操作都带 deadline。
  4. 冒烟踩坑：fake upstream 把整条 query 尾部（含 EDNS OPT）echo 回去再拼 answer、ARCOUNT 写 0 → dig 报 "16 extra bytes / malformed"。 hex dump + 手数偏移定位（多的 16 字节正好是拼上的 A 记录）。 修复 = 只 echo question 段。字节级协议调试方法论从 Rust D1 直接迁移。
  5. 端口坑：macOS Chrome 常驻 UDP :5353（mDNS），run.sh 改用 15353/15300。对应 rs-lab 速查表"环境本身要先标定"：本机端口占用 先 netstat -anv -p udp 看一眼。
