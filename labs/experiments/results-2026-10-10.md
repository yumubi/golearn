## E1. GC 压力账（gc-pressure/）

问题: Go 没有 Rust 的所有权, "每请求分配"到底交多少税?
三形态做同一件事(512B payload 装箱传递 1000 次/op):

协议: `go test -bench . -benchmem -benchtime=10000x -count=5`(钉次数防时间片差异)。

| 形态 | ns/op (5轮区间) | B/op | allocs/op | 机制 |
|------|----------------|------|-----------|------|
| Alloc(裸分配) | 220-239k | 512,002 | 1000 | 每次装箱堆分配, GC 买单 |
| Pool(sync.Pool) | 169–181k | 26,025 | 1004 | buffer 复用, 但 any 装箱每次 1 alloc |
| Reuse(单buffer) | 140–145k | 0 | 0 | ≈ Rust &mut 借用, 零分配零GC |

解读(现象 → 机制 → 对照):

1. **裸分配比零分配慢 1.6×, 且 allocs 1000:0**。分配本身的 malloc 快,
   税在 GC: 见 census：Alloc 跑 10 万次触发 **6 轮 GC**, Reuse 触发 1 轮(启动那轮)。
2. **sync.Pool 不是零分配魔法**: `Get()` 返回 `any` 装箱, 每次 +1 alloc。
   26KB/op 是装箱+New 逃逸的残余。Rust 的 typed_arena 没这个问题：
   类型单态化, 无装箱。Go 要 0 allocs 得类型化 pool(如 `sync.Pool` 存 `*[512]byte`)。
3. **GC 周期数 = 直接证据**: `GODEBUG=gctrace=1` 下 Alloc 基准 20000x 触发 **3721 轮 GC**,
   Reuse 同协议 **21 轮**(177×差距, 全是每请求分配的税)。
   这就是 P6 压测里 Go 版 P50 比 Rust 版高 0.3-0.5ms 的机制解释之一。

census(TotalAlloc 口径, 10 万次操作):

```
alloc : GC cycles=6 total=61 MiB heap_live=52926 KiB   ← 驻留污染前清了 sinkVar
pool  : GC cycles=1 total=2345 KiB heap_live=258 KiB
reuse : GC cycles=1 total=0 KiB    heap_live=256 KiB
```

Rust 对照: alloc ≈ 每次 `Box::new`+move(但所有权转移后 drop 即还,
无 GC 扫描税)。pool ≈ typed_arena(批量还)。reuse ≈ `fn(&mut [u8])`
(编译器强制独占, 零税)。**Go 三种都合法, 税单只有 gctrace 给你**。

### 方法论事故记录(同 bench-hygiene E1)

第一版 Alloc 跑出 **0 B/op 0 allocs/op**：`make([]byte, 512)` 未逃逸,
被栈上分配, 循环只是移动栈指针。这正是 rust-for-frontend 实验里
"local 计数显示 0ms 被 LLVM 折叠"的 Go 版翻版。
修法: Go 没有 `std::hint::black_box`, 把 buf 写进包级 `sinkVar` 切片
强制逃逸是唯一硬手段。教训: **benchmark 的 0 allocs 要先怀疑折叠再庆祝**。

## E2. 共享计数器四方案(counter-battle/)

复刻 rust-for-frontend counters 实验的 Go 版。
8 goroutine × 1,000,000 次 +1, 总和断言 == 8,000,000。
协议: 程序内 15 轮, hot 模式(每次迭代打共享计数)。

| 方案 | min | 中位 | max | 极差 | Rust 原版对应 |
|------|-----|------|-----|------|--------------|
| sync.Mutex | 455ms | 491ms | 522ms | 1.15x | Arc<Mutex<u64>> 节拍器 |
| atomic.Uint64 | 36ms | 96ms | 132ms | **3.62x** | Arc<AtomicU64> 野的 |
| channel → 聚合 | 627ms | 1046ms | 1145ms | 1.83x | mpsc → 聚合线程 |
| 本地计数 + join | 0.4ms | 0.4ms | 0.8ms | 1.84x | thread_local + join |

解读:

1. **Go 的 atomic 比 mutex 快 5×**(Rust 原实验里两者在噪音内)。
   机制差异: Rust 的 `Arc<Mutex<u64>>` 锁路径短(futex 快路径),
   atomic RMW 在 M4 上是 cache line 乒乓主场。Go 的 `sync.Mutex`
   是 starvation-aware 混合锁, 慢路径带 goroutine 挂起/唤醒调度,
   比 futex 折腾：**同样的两种原语, 不同运行时实现, 排名可以反转**。
   跨语言"atomic 一定比锁快"的结论不可移植, 实测为准。
2. **离散度不对称照样成立**: mutex 极差 1.15x(节拍器), atomic 3.62x(野的)。
   与 rust-for-frontend 20 轮补测结论(1.11x vs 1.85x)同构：
   小样本会把"离散度差异"读成"均值一样快"或"排名互换"。
3. **channel 是最慢的共享方式**(中位 1046ms vs atomic 96ms): 每次迭代
   发一条 = 调度+拷贝+唤醒全套。batch 模式(攒 1000 再发)下 channel
   是 2-3ms 级：**channel 的成本单位是"条数"不是"字节"**。
4. 本地计数 + join 比最快共享方案快 90×：**消灭共享永远是最优解**,
   Rust 里这叫"所有权隔离", Go 里叫"别共享, 各算各的"。

5. **-race 只配正确性测试, 不配压测**: race 检测器让 channel 收发慢 10-20×,
   hot 模式 800 万条把 80s 超时跑爆：这不是死锁, 是减速
   (栈特征: 所有生产者停在 `chan send`, 聚合者活着的正常背压)。
   正确路径: `go test -race -run TestCorrectness`(9.6s 过, race 干净)
   与 `go test -run TestBattle`(不开 race, 22s)分开跑。

`run15` 对同一 `MutexCounter` 实例跑 15 轮, 第二轮起总和 = 2×8M,
正确性断言抓出 CORRUPT。修法: `Run` 开头归零。
教训: **正确性断言不是仪式, 它今天真的拦下一个假数据**。
复用计数器必须显式重置(≈ Rust 里 `*counter.lock().unwrap() = 0` 同样要写)。

## E3. benchmark 卫生(bench-hygiene/, 教训汇编)

三个现场翻车, 全部发生在写 E1/E2 的过程中:

| 翻车 | 症状 | 机制 | 修法 |
|------|------|------|------|
| 栈上分配假象 | Alloc 报 0 B/op 0 allocs/op | make 未逃逸, 编译器栈上分配 | 写包级 sink 强制逃逸; Go 无 black_box |
| DCE(死代码消除) | 循环体只剩自增, ns/op 异常低 | 结果未被消费 | keep 变量读回; Go 编译器不保证保留 |
| 复用实例跨轮累积 | 总和断言 CORRUPT 2× | benchmark 多轮复用同一状态 | Run 开头归零; -count=N 必配状态重置 |

外加两条协议规则:

1. **-benchtime=Nx 钉次数**: 默认 1s 自适应会让不同形态跑不同迭代数,
   P/E 核调度噪音下不可比。钉死次数后才谈得上 count=5 区间。
2. **-count=5 报区间不报单值**: E1 的 Alloc 5 轮 220-239k(±4%),
   单轮可能在任一端。与 rust-for-frontend "4 轮样本读出错误结论"教训同源。

### E3 补测: bench-hygiene 包(hygiene.go/hygiene_test.go)

Foldable vs Escaped 同任务(1万次求和), -benchtime=10000x count=2:

| 版本 | ns/op (2轮) | 说明 |
|------|------------|------|
| Foldable(不防折叠) | 3904 / 2620 | 轮间漂移 49%：不消费结果, 优化器行为不稳定 |
| Escaped(包级 Sink) | 3046 / 2826 | 轮间漂移 8%：写包级变量, 路径稳定 |

本机 go1.26.4 编译器没删 Foldable 的循环(还跑了), 但轮间离散度
已经差 6×：**防折叠的收益不只是"防止归零", 还有"压住离散度"**。
单轮 3904 vs 2620 会读出"防折叠更慢"的假结论。
