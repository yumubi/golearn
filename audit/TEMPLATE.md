## 断言台账

列含义：`#` 序号 / `断言（原文位置）` 引文或行号 / `核对方式` 见下表 / `命令或出处` 可复制重跑的命令，或官方文档 URL 加引文，或源码 `文件:行` / `结果` 实际看到了什么 / `状态` 只能是 OK、FIXED。发现不一致必须当场修并标 FIXED，不允许留 OPEN 交付。

| # | 断言（原文位置） | 核对方式 | 命令或出处 | 结果 | 状态 |
|---|---|---|---|---|---|
| 1 | L42 "Handler 接口 4 个方法" | go doc | `go doc log/slog.Handler` | 列出 Enabled/Handle/WithAttrs/WithGroup 共 4 个 | OK |

核对方式取值：`go doc`（API 签名与行为）、`源码`（GOROOT 或 go mod 缓存里读实现）、`重跑`（把笔记里的命令或输出实拍重新执行并 diff）、`计数`（行数、测试数、文件数用 wc/grep 数出来）、`官方文档`（带 URL 与引文）、`引用`（章间 §号、文件路径、测试名真实存在）。

## 必须覆盖的类别（每类至少 2 条，没有该类内容则在下面写明"本章无此类"）

- 版本与依赖：笔记里出现的库版本、Go 版本与 go.mod 对得上
- API 形态：函数签名、返回值个数、方法集、错误值
- 数字：行数、测试数、端口、阈值、性能数据的出处
- 实拍输出：笔记里贴的终端输出，现在重跑是否一致（差异要解释：时间戳、端口、随机数）
- 章间引用：写着"见 P?? §?"的地方，那一节是否真讲了这件事
- Rust 对照：对照里的 Rust 侧说法是否准确（API 名、行为、版本），这类常被忽略
