# 01 Go 的世界观与差异总表

> 详细程度：标准 · 约 20 分钟
> 材料：TB01、TB02、TB00、TBX01 · 旧长版：`notes/p1-toolchain.md`、`notes/p2-lang-core.md`
> 前置：任意一门主流语言

## 这一节要建立的认知

Go 的每个"缺失"都是刻意的取舍，不是还没做到。作者归纳为五条：**简单、显式、组合、并发、面向工程**。〔TB02 p10-11〕

这五条是后面所有章节的判断标准。读到任何一个"为什么 Go 不提供 X"的问题，先回到这里：多半是因为 X 违反了其中一条。

## 一、五条设计哲学，各自落在哪

| 哲学 | 含义 | 语言里的证据 |
|---|---|---|
| 简单 | 做减法，少而足够，保持生产力 | 25 个关键字；没有类、构造函数、继承、结构化异常〔TB02 p2-3〕 |
| 显式 | 没有暗箱操作，开发者要知道每个操作 | `int16` 与 `int` 不能直接相加；错误经返回值上抛〔TB02 p3-5〕 |
| 组合 | 降低耦合，靠组合而非层级扩展 | 类型之间没有父子关系；接口隐式满足；包独立〔TB02 p5-8〕 |
| 并发 | 面向多核，并发是结构设计方法 | goroutine、channel、select 内建；栈初始 2KB〔TB02 p8〕 |
| 面向工程 | 把构建慢、依赖乱、代码难读这类问题纳入语言设计 | 未使用的导入无法编译；禁止包循环依赖；故意没有默认函数参数；gofmt〔TB02 p9-10〕 |

"显式"这一条值得单独看一眼，它是多数迁移者的第一个绊脚石：

```go
var a int16 = 1
var b int = 2
fmt.Println(a + b)
```

```text
invalid operation: a + b (mismatched types int16 and int)
```

C 会悄悄做类型提升，Go 要求你写出转换。错误处理也一样：没有隐含的控制流跳转，社区提过的带隐式成分的新方案都被否决了。〔TB02 p5〕"面向工程"的另一个例子：导入但没用的包是编译错误（`"os" imported and not used`），不是警告，这让依赖树始终精确，构建也不会编译多余代码。〔TB02 p9〕

## 二、和你已知语言的差异总表

| 维度 | Java / Kotlin | Rust | TS / JS | Go |
|---|---|---|---|---|
| 类型检查 | 静态强类型 | 静态强类型 | 静态（擦除），运行时动态 | 静态强类型，变量类型不可变〔TBX01 p2-4〕 |
| 复用手段 | 继承、默认方法 | trait、泛型 | 继承、mixin | 嵌入加接口，无继承 |

| 可见性 | `public`/`private` | `pub` | `export` | 标识符首字母大写即导出〔TB04 p7〕 |
| 默认参数、重载 | 有 | 无重载，有宏 | 有 | **都没有**，故意的〔TB02 p9〕 |

## 三、几个值得多想一步的取舍

1. **没有异常，不等于没有 panic**。panic 表示程序即将崩溃，API 内部要消化它并转成 `error` 返回。〔TB02 p14〕
2. **运行时随二进制一起交付**。垃圾回收、并发调度、栈管理都在 runtime 里，hello world 也带着它。所以 Go 程序是单个静态二进制，部署简单，代价是二进制偏大。〔TB01 p12-13〕
3. **有兼容性承诺，也自带电池**。Go 1.0（2012）起承诺符合 Go1 规范的源码保证向后兼容，这是十年前的代码今天还能编译、语法特性极少变化的原因。〔TB01 p7〕`net/http`、`crypto`、`encoding` 直接支撑生产级服务，第三方依赖可以少很多。〔TB02 p9-10〕
4. **标准库里的设计是范本**。`http.HandlerFunc` 是 Russ Cox 利用"函数是一等公民，且可以拥有方法"设计出来的；`io.Reader/io.Writer` 奠定了 Go 的 I/O 结构。想学地道写法，读标准库。〔TB01 p5〕〔TB00 p12〕

## 四、迁移者最常见的七个错误直觉

作者把"用其他语言的思维写 Go"称为"形神皆丧"，并指出另一个根本问题是没有建立"设计意识"：能选对语言元素搭出程序骨架。〔TB00 p6〕

1. **用类和继承建模**：改成小结构体、小接口、嵌入，见 04 节。
2. **用 panic 当异常**：错误是常态，走返回值，见 05 节。
3. **把 goroutine 当免费的**：创建便宜，但每个都要有退出路径，见 06 节。
4. **提供方先写接口**：Go 的接口由使用方定义，见 04 节。
5. **给每个字段写 getter 和 setter**：Go 习惯直接访问字段，只在需要不变量时加方法。〔TBX04 p11-12〕
6. **想要最新版依赖**：Go 取满足所有依赖方要求的最小版本，构建可重现，见 02 节。
7. **先找大而全的框架**：先看标准库够不够。

给新语言做体检也有快办法：先问强类型吗？静态还是动态？内建类型有哪些？有结构体、字典、泛型吗？〔TBX01 p1-2〕回答这些再读规范，比从头读语法快。Go 的答案是：静态强类型，原生复合类型（数组、切片、map、结构体、channel），泛型有但克制。

## 在项目里

`dnsproxi-go/` 把这些取舍具体化（module 与目录布局见 02 节）：入口 `main` 函数先 `loadConfig()` 读环境变量，再 `newLogger`，最后 `Proxy.Run`，失败时 `logger.Error` 并 `os.Exit(1)`，没有异常也没有隐式初始化。`cache/cache.go` 的 `Cache` 里直接放一个 `mu sync.RWMutex` 字段，零值即可用，不需要单独初始化（三张 map 则由 `NewCap` 建好，nil map 不能写）。
