# 风格样张（正样， PROMPT 少样本用）

来源：澄清文档样张 C2（叙事开法）与样张 D（机制层深度），2026-11-03 所有权人核准。

## 样张 C2 · 提纲挈领的叙事开法（多态节开头）

你已经会用 Java 的多态：声明一个 `Sender` 接口，让 SMS、Email 各自 `implements`，然后拿父类引用指向子类对象。现在把这套搬进 Go，你会发现 `implements` 这个关键字不存在了，但多态还在。这一节就讲两件事：**关系怎么建立**，和**调用怎么发生**。

先看关系。Go 不要求类型声明"我实现了谁"；只要你的方法集合里凑齐了接口要求的方法，赋值的那一刻关系就成立了。这带来一个 Java 给不了的自由：你可以给标准库的类型配一个自己定义的接口，因为不需要改对方的源码。

再看调用。写下一行 `sender.Send("hi")` 时，编译器不知道 `sender` 里装的是谁，它生成的指令是：查这个组合的 itab，取函数地址，间接跳转。Java 的 `invokeinterface` 做的也是这件事，所以性能不用担心，两者同量级。

那 Java 的继承呢？Go 把这条路堵死了：没有 extends，嵌入只是编译期把内层方法"抄写"到外层，内层方法被调用时，接收者永远是内层自己，不存在虚方法。想要"调用方不改一行代码、行为随实现变"，Go 只剩接口这一条路。这也是为什么 Go 社区说：复用靠嵌入，多态靠接口。

## 样张 D · 机制层深度（接口调用的运行时行为）

同一行 `sender.Send("欢迎注册")`，编译器生成的是间接调用：`sender` 不只是"一个值"，它是一个两字结构 `(类型信息, 数据指针)`。类型信息里存着这个"接口 × 具体类型"组合的方法地址表 itab；调用时取 `itab.fun[0]` 间接跳转。Java 的 `invokeinterface` 做的是同一类事，查 vtable 槽位再调用。所以两种多态的**运行时成本同量级**，真正的差异在**关系怎么建立**：
