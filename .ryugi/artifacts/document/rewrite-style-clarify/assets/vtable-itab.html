Java · 编译期生成虚方法表

class SMS implements Sender {
    public void send(String m) { ... }
}
// javac 把类的方法指针写进
// klass 的 vtable 槽位
// invokeinterface → 运行时查槽
关系写死在类定义里 · 继承树

Go · 运行时按需构建 itab

type SMS struct{}
func (SMS) Send(m string) { ... }
// 首次 Sender = SMS{} 时，runtime
// 缓存 itab{inter, _type, fun[]}
// 接口调用 → itab.fun[i] 间接调用
关系在使用点成立 · 方法集合
共同点：都是"查方法地址表 → 间接调用"，动态分派成本同量级。差异：Java 的表是每个类的单一 vtable（单继承布局），Go 的 itab 是"接口 × 具体类型"的组合表——所以 Go 不需要 implements 声明，但每种组合要构建一次。
